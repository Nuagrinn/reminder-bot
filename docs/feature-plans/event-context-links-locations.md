# Контекст события: ссылки и адреса

Дата: 2026-07-27
Статус: MVP implemented

## Проблема

В напоминании может быть полезный контекст, который не является ни названием,
ни датой, ни временем:

```text
Завтра в 14:00 собес/скрининг, ссылка в телемост:
https://telemost.yandex.ru/j/63566773415847
```

Сейчас бот корректно создает событие, но ссылка теряется: в модели события нет
отдельного места для ссылок, адресов и похожих сущностей. Та же проблема будет
с адресами:

```text
Завтра в 19:00 встреча, адрес: Москва, Никольская 10
```

Нужен отдельный слой контекста события, чтобы в момент напоминания не приходилось
искать исходное сообщение в Telegram.

## Проверенные возможности Telegram

По официальному Bot API сейчас доступны:

- URL-кнопки в inline-клавиатурах через `InlineKeyboardButton.url`;
- настройка предпросмотра ссылок через `LinkPreviewOptions`;
- отправка точки или места через `sendLocation` / `sendVenue`, но для этого
  нужны координаты;
- Rich Messages с блоками списка/таблицы/карты в Bot API 10.x, но для MVP лучше
  остаться на текущем HTML-рендерере и inline-кнопках.

Вывод:

- ссылки в MVP надо показывать обычной кнопкой `Открыть ссылку`;
- предпросмотр ссылки можно включать только в detail/due-карточках, но нельзя
  считать его хранилищем;
- адреса сначала стоит хранить как сырой текст, а координаты и `sendVenue`
  добавить позже.

Источники:

- https://core.telegram.org/bots/api#inlinekeyboardbutton
- https://core.telegram.org/bots/api#linkpreviewoptions
- https://core.telegram.org/bots/api#sendlocation
- https://core.telegram.org/bots/api#sendvenue

## Рекомендуемый MVP

Добавить отдельную таблицу `event_contexts`. У одного события может быть
несколько контекстных элементов: несколько ссылок, адрес, комментарий.

```text
event_contexts
  id TEXT PRIMARY KEY
  event_id TEXT NOT NULL
  kind TEXT NOT NULL          -- link | address | note
  label TEXT NOT NULL         -- Телемост, Адрес, Карта
  value TEXT NOT NULL         -- URL или сырой адрес
  normalized_value TEXT       -- canonical URL или нормализованный адрес
  source TEXT NOT NULL        -- extracted | parser | manual
  position INTEGER NOT NULL
  created_at TEXT NOT NULL
```

Реализовано в `004_event_contexts.sql`.

Почему лучше таблица, а не JSON внутри `events.description`:

- у события естественно может быть больше одной ссылки;
- из структурных строк легко строить URL-кнопки;
- будущий геокодинг можно добавить без перепарсинга старых описаний;
- списки останутся компактными, а подробные карточки смогут показывать контекст.

## Разбор текста

Ссылки лучше извлекать детерминированно, до или параллельно с Claude:

1. Найти URL в исходном тексте регуляркой/URL-парсером.
2. Сохранить URL точно как в сообщении.
3. Убрать URL и фразы вроде `ссылка в телемост` из кандидата на title.
4. Claude оставить задачу смысла: название, дата, время, повторяемость.
5. Ответ Claude с контекстом использовать как подсказку, а не как единственный
   источник ссылок.

Расширение схемы парсера:

```json
"context": {
  "links": [
    {"url": "...", "label": "Телемост"}
  ],
  "locations": [
    {"address": "Москва, Никольская 10", "label": "Адрес"}
  ]
}
```

Для compact-ответа Claude стоит поддержать синонимы:

- `url`, `link`, `links`;
- `address`, `location`, `place`, `venue`.

Реализовано:

- детерминированное извлечение `https://`, `http://`, `www.`, `tg://`;
- метки для частых доменов: Telemost, Zoom, Google Meet, Google Docs,
  Google Drive, Google Forms, Teams, Notion, GitHub, Figma, Telegram;
- дедупликация одинаковых URL;
- parser label может заменить доменную метку, например `Бронь`;
- `context` добавляется в native/compact payload до сохранения.

## Адреса

MVP:

- сохранять сырой адрес;
- показывать его в подтверждении, detail-карточке и напоминании;
- строить кнопку карты через поисковый URL:
  `https://yandex.ru/maps/?text=<encoded address>`.

Реализовано для явных фраз:

- `адрес: ...`;
- `по адресу ...`;
- `адрес встречи: ...`;
- `адрес доставки: ...`;
- `место: ...`;
- `локация: ...`.

Позже:

- добавить опциональный геокодинг;
- хранить `latitude` / `longitude`;
- при наличии координат использовать `sendVenue` или точную ссылку на карту;
- принять Telegram-location от пользователя как отдельный источник адреса.

## UX в Telegram

Подтверждение:

```text
Проверь напоминание

Собес/скрининг
Когда: 28.07.2026 14:00
Ссылка: Телемост
```

Карточка после сохранения:

```text
Запланировал

Собес/скрининг
Событие: 28.07.2026 14:00
Ссылка: Телемост
```

Напоминание/detail:

```text
Напоминание

Собес/скрининг
План: 28.07.2026 14:00
Ссылка: Телемост
```

Кнопки для события со ссылкой:

```text
[Открыть ссылку]
[Готово]
[Напомнить +1ч] [На завтра]
[Перенести]
[Удалить]
[Скрыть]
```

Для адреса:

```text
[Открыть карту]
```

Списки на день/неделю/месяц должны остаться компактными. URL целиком не
показываем; строка получает заметный маркер перед названием:

```text
1 14:00 🔗 Собес/скрининг
2 вечер 📍 Встреча
```

## Открытые вопросы и дальнейшие шаги

- Кнопки сейчас подписываются по провайдеру/домену. Можно расширять словарь
  меток по мере реальных ссылок.
- Полный URL не показывается в карточках, чтобы не перегружать Telegram UI.
- В списках показываются короткие маркеры `🔗` / `📍` перед названием.
- Какой геокодер брать позже: Yandex Maps, Google Maps или OSM/Nominatim?
- Нужна ли отдельная команда/экран для редактирования ссылок и адресов после
  создания события.
